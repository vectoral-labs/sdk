# Fingerprinting

Two unrelated things share the name. Keeping them apart matters, because they
run in different places, carry different trust, and use different salts.

| | Device fingerprint | Prompt fingerprint |
| --- | --- | --- |
| Identifies | a browser | a piece of text |
| Runs in | the browser (`@vectoral/browser`) | your server (`@vectoral/sdk`) |
| Salt | publishable site key | secret tenant salt |
| Answers | "have I seen this device before?" | "have I seen this prompt before?" |
| Trust | soft — attacker-controlled | strong — computed by you |

## Device fingerprints

```js
import { deviceFingerprint } from "@vectoral/browser";
const { fingerprint, strong, coverage } = await deviceFingerprint({
  siteKey: "pk_live_abc",
});
// fingerprint -> "fp_9c1e4a7b…"
```

Send it to your backend, which forwards it as `device_fingerprint`. It is the
**highest-value optional field on a registration**: one device across many
signups is the strongest farm signal that exists, and it is invisible without
it. If you wire up exactly one optional field, wire up this one.

Vectoral never interprets the value, only compares it — so any stable
client-side identifier you already compute works just as well. It only needs to
be consistent with itself. Do not send anything that identifies a person.

### Stability is the design constraint

An identifier that churns is worse than none: it resets for every legitimate
user while costing an attacker nothing. So the components are chosen for
stability as much as for entropy, and three obvious ones are deliberately
excluded:

- **the full user-agent string and browser version** — changes on every browser
  update, which would reset every honest user's fingerprint roughly monthly.
  Brand *names* are included; versions are stripped.
- **window size and `devicePixelRatio`** — change with zoom and window dragging.
- **`navigator.plugins` contents** — empty on modern browsers; no signal left.

What remains: platform, brand names, language, timezone, screen geometry,
hardware concurrency, device memory, touch points, WebGL vendor/renderer, and a
canvas rendering.

### What the result tells you beyond the value

- `strong: false` means SubtleCrypto was unavailable (an insecure context) and a
  non-cryptographic fallback hash was used. The value is still stable and still
  comparable — it is just cheap to reverse, so do not treat it as a privacy
  boundary. If you see this in production, you are serving over `http://`.
- `coverage: { present, total }` counts how many components resolved. A very low
  count is itself a signal: it means a hardened or headless browser. Log it.

### Trust

The fingerprint is computed on the abuser's machine. It can be forged, replayed,
or stripped. Treat it as a **correlation key, not evidence** — it says two
signups came from the same browser, not that either was fraudulent. See
[salts](salts.md) for why no amount of client-side secrecy would change this.

## Prompt fingerprints

A privacy-preserving digest of prompt text, computed on your server. It lets
Vectoral detect accounts running identical or near-identical prompts — the
signature of a reseller farm — **without the prompt text ever leaving your
process**.

```ts
const vectoral = new Vectoral({
  apiKey: process.env.VECTORAL_API_KEY,
  fingerprint: { enabled: true, salt, saltId },
});

await vectoral.inference.score({
  account_id: "user_1",
  request: { prompt_text_to_fingerprint: userPrompt },  // never sent
});
```

`prompt_text_to_fingerprint` is a local-only input. The SDK strips it from the
outgoing body **unconditionally** — including when fingerprinting is disabled,
so a config change can never start leaking prompts. It is also entirely separate
from `prompt_text`, which is the Deep Mode field.

### What is computed

| Component | What it catches |
| --- | --- |
| `exact_hash` | byte-identical prompts |
| `simhash` | near-identical prompts — reworded, renamed, lightly edited |
| `minhash` + `band_keys` | efficient near-duplicate lookup at scale |
| `conversation_key` | messages belonging to the same conversation |
| `simhash_global` | the same, comparable across customers (opt-in) |

Text under an 8-token floor produces **no fingerprint at all**. There is not
enough material for a stable digest, and a noisy one is worse than a missing
one.

### Cross-language correctness

The TypeScript implementation is a port of the normative Go one. The port is
verified against golden vectors generated by Go, vendored at
`typescript/packages/sdk/src/fingerprint/testdata/test_vectors.json`, and every
vector must reproduce bit-exactly.

**On a mismatch, fix the TypeScript side.** Never regenerate the vectors from
TypeScript — they are the contract, and a fingerprint that disagrees across
languages is a fingerprint that matches nothing. Refresh them from the Go repo
with `scripts/sync-fingerprint-vectors.sh`.
